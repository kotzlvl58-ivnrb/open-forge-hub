# OpenForge Hub

An open catalog of local AI artifacts — models and datasets — distributed over **BitTorrent**.
MIT licensed. Downloads are free, forever.

Built with **React + Vite + TypeScript + Tailwind CSS v4**, running **WebTorrent** in the
browser for small transfers, and standard magnet links (with web seeds) for everything else.

---

## Why torrents?

Model files are huge, re-downloaded constantly by the community, and painful to serve from a
single origin. BitTorrent turns that cost into a network effect:

| | Centralized CDN (hosting platform) | Torrent hub (this project) |
|---|---|---|
| Popular release | Egress bill explodes | Gets *faster* as more people download |
| Cold/rare release | Fine, server serves it | **Web seeds (BEP 19)** guarantee availability |
| Host disappears | Files 404 | Swarm + web seeds keep files alive |
| Integrity | Trust the server | Info-hash is a cryptographic commitment + SHA256SUMS |

Every magnet generated by the app carries:
- `xt` — the info-hash (content address),
- `tr` — tracker announce URLs,
- `ws` — an HTTPS **web seed** so downloads never depend on a live swarm.

> The demo info-hashes in `src/data/models.ts` are syntactically valid placeholders,
> not real torrents.

## Architecture

```
src/
  data/models.ts        # Catalog + torrent metadata (swap for an API later)
  data/monetization.ts  # Single source of truth for sponsorships/ads config
  lib/format.ts         # Bytes, dates, magnet URI builder (hand-built, see note)
  lib/torrentClient.ts  # Lazy-loaded WebTorrent wrapper (dynamic import)
  lib/uint8Polyfill.ts  # Uint8Array base64/hex polyfill for pre-2025 browsers
  lib/stubs/            # bittorrent-dht browser stub
  state/downloads.tsx   # Live download progress across pages
  state/support.tsx     # Backer mode (hides ads when active)
  components/           # ModelCard, DownloadPanel, AdSlot, SponsorStrip, layout, icons
  pages/                # Home, Explore, ArtifactDetail, Downloads, Publish, About, Support, 404
```

Key decisions:

- **HashRouter** — the built site works from any static host (GitHub Pages, S3, IPFS…).
- **Lazy WebTorrent** — the ~137 KB (gzip) torrent chunk loads only when a user clicks
  "Download in browser". Catalog/marketing pages never pay that cost.
- **Magnets are built by hand**, not with `URLSearchParams`, which percent-encodes
  `xt=urn:btih:…` into something `magnet-uri` parsers reject.
- **WebTorrent v3** (2026) fixes an upstream bug where `arr2hex()` was called on the
  string info-hash during `client.add()`.
- **Vite config** carries three browser-compat shims (documented inline):
  `vite-plugin-node-polyfills` for Node core modules, a `bittorrent-dht` stub, and a
  virtual `bittorrent-protocol/mse.js` stub for the production build.

## Monetization (without paywalling downloads)

The business model: **visibility and goodwill, never gated files.**
All configuration lives in `src/data/monetization.ts`.

### Ready now (in the UI)

1. **Recurring tiers** (Lurker $3 / Seeder $8 / Swarm $20) with perks that don't touch
   downloads: name on the supporters page, artifact requests, featured-model vote,
   logo placement. Wire `MONETIZATION.tiers.checkoutBaseUrl` to Stripe Payment Links,
   GitHub Sponsors, or Patreon — no code changes needed beyond that field.
2. **One-off contributions** (Ko-fi-style). Set `MONETIZATION.oneOff.url`.
3. **Partner slots** (`<AdSlot>` component) — clearly labeled, never interstitial,
   hidden entirely for supporters. Set `MONETIZATION.ads.networkTagId` to activate an
   external network (Adsterra, a-ads, EthicalAds); the house promo shows otherwise.
4. **Backer mode** — after becoming a supporter, ads disappear site-wide
   (`state/support.tsx`). This is the honest promise of the model.

### Roadmap ideas (revenue without gatekeeping)

- **Mirror-as-a-service for publishers**: backing includes burst web-seed hosting for
  new releases (already referenced on the Publish page).
- **Featured placement**: paid "spotlight" badges clearly separated from organic rank.
- **Corporate sponsorship**: logo on the backer wall + a "funded by" strip.
- **Swarm health API** for third-party dashboards (metered, not downloads).
- **Fiat-to-seedbox bridges**: paid seeding capacity that the *community* benefits from.

### Explicitly rejected

- Paid downloads, download quotas, "premium speed", account-gated files, crypto miners,
  or any pattern that treats the swarm as a paywall.

## Legal notes

- BitTorrent is a neutral protocol. This project indexes only artifacts whose licenses
  permit redistribution, and provides a takedown process (24h target).
- Every listing declares its license (`MIT`, `Apache-2.0`, `OpenRAIL-M`, `CC-BY-*` …);
  reviewers verify the license story before listing.
- `SHA256SUMS` files ship inside torrents; the info-hash additionally pins the exact
  byte layout, so integrity is verifiable end-to-end.
- This codebase is **MIT licensed** (see `LICENSE`). It is an original work — inspired
  by the *concept* of open model hubs, not a copy of any site's code, design, or assets.

## Running locally

```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # tsc -b
npm run build      # dist/ ready for any static host
npm run preview    # serve the production build
```

Requirements: Node ≥ 20.

## In-browser downloads vs native clients

| | In browser (WebTorrent) | Native client (qBittorrent, Transmission, aria2) |
|---|---|---|
| Small files, previews | ✅ ideal | overkill |
| Multi-GB weights | ❌ WebRTC-only peers | ✅ recommended — use the magnet |
| Selective file download | after download (Blob save) | ✅ before download (`--select-file`) |

The demo catalog's info-hashes have no real swarm, so in-browser downloads will show
"Looking for peers…" indefinitely — with a real torrent (and its web seed) they complete.

## Deploying to Vercel

The project is Vercel-ready out of the box:

- `vercel.json` — Vite framework preset, `npm run build`, `dist/` output, a SPA rewrite
  (harmless with HashRouter but future-proof if you switch to BrowserRouter), immutable
  caching for hashed `/assets/*`, and basic security headers.
- `.nvmrc` — pins Node 20 for build reproducibility.
- `.gitignore` — excludes `node_modules/`, `dist/`, and `.vercel/`.

### One-click (dashboard)

1. Push the repository to GitHub/GitLab/Bitbucket.
2. [vercel.com/new](https://vercel.com/new) → import the repo.
3. Vercel auto-detects Vite. No environment variables are required.
4. Deploy — every push to `main` gets a production deployment, every PR a preview.

### CLI

```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production deployment
```

### Notes

- The app is a pure static SPA — no serverless functions, no secrets to configure.
- Adding env vars later (e.g. a catalog API URL): set them in the Vercel dashboard and
  read them via `import.meta.env.VITE_*` in code; never commit `.env` files.
- If you add routes, no Vercel config change is needed — the rewrite already covers
  arbitrary paths.
